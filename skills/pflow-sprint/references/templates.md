# Sprint 文件模板

每个 sprint 是 `ai/sprints/active/<name>/` 下的核心三件套 + 产物目录（跨会话交接时再加 HANDOVER.md）：

| 文件 | 职责 | 生命周期 |
|------|------|----------|
| BRIEF.md | 目标、成功标准、范围 | 创建时写入，之后不修改 |
| PLAN.md | 步骤拆分、涉及文件、验证方式、内联状态 | 创建时写入，推进中更新状态 |
| LOGBOOK.md | 决策记录 + 踩坑记录（派 subagent 的 sprint 另有执行进度段） | 按需追加 |
| HANDOVER.md | 跨会话交接的当前快照 | 仅跨会话时创建，整段覆盖 |
| artifacts/ | demo/截图/脚本等非文档产物 | 随用随存 |

---

## BRIEF.md

```markdown
# Sprint: <标题>

## 创建时间
YYYY-MM-DD

## 问题描述
<2-3 句话说明要解决什么问题>

## 成功标准
- [ ] <具体的、可验证的标准>

## 范围
- 包含: <涉及的文件、模块、功能点>
- 不包含: <明确排除的内容>
```

---

## PLAN.md

```markdown
# 计划

## 执行编排
> 复杂 sprint 才填；简单的删掉本段。sprint 节奏见 pflow-sprint/references/orchestration.md，派活做法见 dispatch skill
- 实现: <主会话亲做 / subagent（opus 或 sonnet）>，段内连续 Step 由同一 agent 推进
- 提交: <执行者提交（用户已授权） / 不提交>
- 审查与验收: 段末检查点派一个独立 agent 兼做（审代码、跑全量、扫残留），改动大或高风险时拆两个并行；<可叠加 codex 交叉审查>；主会话把关
- 运行形态: <交互式 / loop>（起停进程、改数据库结构或真实数据、不可逆操作的段强制交互）
- 危险操作: 主会话亲做，或经用户确认后做

## Step 1: <标题> [ ]
- 涉及: <文件列表或产出物>
- 内容: <具体做什么>
- 验证: <如何确认完成>

## Step 2: <标题> [检查点] [ ]
- 内容: 汇总已完成工作与决策，与用户确认后再继续
- 验证: 用户确认
```

**状态标记**（内联在标题末尾）：
- `[ ]` pending
- `[wip]` in-progress
- `[done]` completed
- `[skip]` skipped

**Step 标注**：
- `[检查点]`: 到达时汇总已完成工作 + 决策，与用户确认后再继续

## HANDOVER.md（仅跨会话时创建）

独立小文件，承载"当前快照"。从 LOGBOOK 拆出来单独成文，是为了改/读它都不必载入整个 LOGBOOK——省掉每次会话交接的反复读写。单会话完成的 sprint 不必建。

```markdown
# 交接

当前状态: <一句话>
下一步:
1. <具体行动，含可执行的命令>
2. ...
注意事项: <警告或前提>
```

**写入规则**：
- 仅在会话即将结束但 sprint 未完成时整段覆盖更新
- 保持短——当前状态一句 + 下一步 1/2/3 + 注意事项即可。待拍板项、已结束的策略说明等临时状态不往这里堆（属决策记录或直接呈报用户），否则每次整段重写都在重复烧 token

---

## LOGBOOK.md

```markdown
# 日志

## 状态: active

---

## 执行进度

（仅派 subagent 执行的 sprint：主会话从执行者回报摘入跨 Step 接口契约；不派 subagent 时删掉本段）

---

## 决策记录

（按需追加，无决策则留空）

---

## 踩坑记录

（sprint 结束时提取，无踩坑则留空）
```

**写入规则**：
- 执行进度段（仅复杂编排 sprint）: Step 完成时由主会话从执行者回报摘入跨 Step 接口契约，只写指针 + 关键对接点，细节落 `ai/scratch/`；审查报告原文同样落 scratch，不进 LOGBOOK（见 orchestration.md「交接分层」「段与检查点」）
- 决策记录: 遇到决策分岔时追加，格式见下方
- 踩坑记录: sprint 结束时提取教训

### 决策条目格式

```markdown
### D1: <决策标题>
- 日期: YYYY-MM-DD
- 选项: <A> / <B>
- 决策: <最终选择>
- 理由: <为什么>
- 影响: <后果或需要的调整>
```

### Sprint 结束时追加的总结段

Sprint 完成或关闭时，在 LOGBOOK.md 末尾追加（状态段同步更新）：

```markdown
---

## Sprint 总结

### 状态: <completed / closed>
### 周期: YYYY-MM-DD -> YYYY-MM-DD
### 关闭原因: <中断 / 放弃 / 方向变更>（completed 时删除此行）

### 目标与结果
| 成功标准 | 结果 |
|---------|------|
| <标准> | pass/fail/partial |

### 未完成的工作（closed 时填写）
- Step N: <标题> -- <原计划内容>

### 后续注意事项
- <脆弱区域或假设变更>
（无则省略此段）
```
